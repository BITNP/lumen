# 以播放为中心的播放队列：预合成、开播同步与无缝接管

旧管线（ADR-0003 时代的 `app.py`）以合成轮次为中心：轮次 worker 顺序走单元，lookahead
槽位一次只预取一句，stop 立即掐断音频并清空一切。实机暴露三个问题：快速输入多条后
打断，旧响应仍逐条合成逐条播出（worker 的 lookahead/synth_next 活在局部变量里，
取消交付有竞态；且 stop 的"立即掐断 + 静默等待新合成"让模型倾向于不发 stop，capability
描述只是建议性措辞）；`emotion/motion` 在单元出队时（合成开始前 3~8s）就发给呈现进程，
动作先于播放；句间空窗靠打补丁式的 lookahead 重试维持。

我们决定把合成与播放（含字幕）整体重写为**以播放行为为中心的统一播放队列
（playback queue）**，最小化处于 idle/静默的时间：

- **一个队列，队头即播放**。输出单元按到达顺序入队为播放任务；`tasks[0]` 是队头，
  播放循环只播队头。
- **后台串行预合成**。一个后台合成 worker 永远沿队列顺序合成"最靠前的未合成任务"并
  缓存整句 PCM（预合成）：队头边合成边播放（流式）；队头合成完，worker 立即合成下一个，
  不管队头播没播完；队列往后全部合成完才空闲。首声延迟因此等于"入队到首块"，与播放进度无关。
- **一切表现事件与开播同步**。PPT 翻页、`emotion`、`motion`、字幕切换、口型
  （speech_state）统一在**开播**时刻触发——即该任务第一个音频字节交给播放器的瞬间
  （无音频的纯视觉单元在成为队头时被执行的时刻）。杜绝"动作先做、声音未到"。
- **stop 不打断当前音频，只做无缝接管**。控制单元 `control:"stop"` 的新语义：
  1. 立即取消进行中的后台合成任务，丢弃所有**尚未开播**的任务（含未开播的队头）；
  2. **不停止正在播放的队头**——它继续播；
  3. 布防接管：stop 之后入队的新任务一旦其音频就绪（见下"首块就绪"），立刻停止当前
     队头播放、出队，马上开播新任务；
  4. 若当前队头先自然播完而新任务尚未就绪，队头按完成出队，进入 idle/等待（字幕不清除），
     新任务就绪后照常开播。
- **首块就绪即接管**（对"开始合成即准备好播放"的事实修正）：audio.cpp 首块延迟实测
  3~8s，若在"开始合成"时刻就掐当前队头，制造的是最长数秒的静默空窗，直接违背本 ADR
  的最小化静默目标；因此"准备好播放"落实为**该任务第一个 PCM 字节可用**。
- **流式路径不做 RTF>1 检测**。若合成持续慢于播放，用户听得出断断续续，应主动切换
  非流式/更快的引擎路径，模块不做自动降级。
- **句间停顿语义不变**：上一句自然播完到下一句开播的最少间隔，合成等待计入不叠加；
  但无缝接管的开播不等待句间停顿（接管就是立即性优先）。
- **queue_finished 心跳**：stop 丢弃了任务时立即发 interrupted 变体（旧轮次已清空）；
  队列真正排空（含 stop 后幸存队头与新任务的续播）后再发完成变体。两者独立，被打断
  报告不代替排空心跳，否则 Agent 的 Invocation 循环会断链。
- **失败不断轮次**：某句合成失败回 error result、跳过该句、继续下一句；不再像旧实现
  那样整个轮次异常终止（旧行为会连排空心跳都发不出去）。

本 ADR 取代 ADR-0003 中"stop 清空队列并立即停止当前播放"的打断语义与 GLOSSARY 旧
控制单元定义；分句单元、列表顺序=表演顺序、受理语义 result 不变。话权与"是否打断"
仍由核心 Agent 决定（waycast ADR-0011）：presenter 的补救是把 stop 的语义与"打断必须
首发 stop 单元"写进 OUTPUT_SCHEMA 与 capability description（描述即契约，经能力目录
注入系统提示），让模型有可靠动力发 stop；模型不发 stop 时 presenter 绝不擅自吞单元。

## Consequences

- `app.py` 的轮次 worker / `_Synth` / lookahead 全部删除，新实现收敛在
  `presenter/playqueue.py`（`PlaybackQueue`：任务表、合成 worker、播放 worker，
  以 50ms tick 轮询谓词协调、无跨任务通知原语），`app.py` 只剩 hub 胶水与
  queue_finished 装配。
- 预合成缓存整句 PCM（16 kHz mono s16le，约 32 KB/s），内存代价可忽略；引擎同时
  在飞合成数从 ≤2 收敛为恒 ≤1，CosyVoice 并发额度更宽裕。
- stop 的 result 明细回报丢弃数；status 的 `queue_depth` 改为"队头之外等待的任务数"。
- 呈现桥协议与 Godot 端零改动（消息形状不变，只改到达时机）。
