# 按句一单元、列表顺序即表演顺序、接收即回 result

输出单元的粒度决定核心与模块的职责边界。我们决定：**核心 Agent 按句派发，一句一个
输出单元**，单元列表的顺序就是表演顺序；单元携带 `speech/subtitle/emotion/motion`
等可选字段，PPT 指令作为句间单元的字段按序执行；打断不设专门消息，用只含
`control:"stop"` 的控制单元（清空队列并立即停止）加新句单元表达（ADR-0011 的"停止
当前语音"）。`result` 帧是**受理语义**：入队成功立刻回 ok，队列满/解析失败回 error；
播放真正完成由 `queue_finished` 输入帧回报（见 ADR-0004）。

被否决的选项：整段粗粒度单元——会把分句与句间插 PPT 指令的编排漏回给核心或迫使模块
再分句，且句级 result 与打断粒度都拿不到。"按句不降延迟"是已知事实：waycast 的
Invocation 跑完多轮工具循环才产出整个列表，按句的收益在粒度与控制，不在首声延迟；
首声延迟由模块内逐句流式合成 + 预取下一句来压缩。

## Consequences

- "一次一句、按句拆分表达"的提示语义写进本模块 capability 的 description（描述即
  契约，经 waycast 能力目录注入系统提示），不修改核心提示词。
- 分句、逐句流式合成、预取、音频缓冲拼接全部是模块内部实现，核心不感知。
